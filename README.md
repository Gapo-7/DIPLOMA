# Alau Term

Наш дипломный проект посвящён сайту поставщика котельного оборудования и инженерного сервиса в Казахстане. Мы хотим сделать каталог, через который можно найти оборудование или запчасть, узнать об услуге и оставить заявку. Интерфейс планируем вести на русском и казахском языках. Тему и набор функций предварительно согласовали устно с представителем Alau Term; подробные требования ещё фиксируем.

## Что уже есть

В `prototype/snapshot/` лежит сохранённый снимок публичных страниц: русская и казахская версии, каталог, услуги и страницы компании. Мы перенесли его по семи этапам; история Git и PR показывает вклад каждого участника. [Аудит снимка](docs/snapshot-audit.md) нашёл 1 234 сохранённые страницы из 2 252 адресов исходного sitemap. Снимок нужен как прототип интерфейса и исходный материал, он не является готовым приложением: формы не обрабатываются сервером, а некоторые страницы и изображения отсутствуют. Ограничения перечислены в [заметках об импорте](docs/import-notes.md).

## Что делаем в дипломе

Планируем реализовать каталог и поиск, заявки на оборудование и сервис, управление обращениями и содержимым, RU/KK сценарии и проверку качества. Для первой версии предлагаем Django с серверными шаблонами и PostgreSQL. Это пока техническое предложение; сравнение альтернатив и причины выбора приведены в [материалах к 20 октября](docs/predefense/README.md).

Там же находятся распределение работ, требования, критерии приёмки, диаграммы, обзор источников, сравнение существующих систем, план проверки и сроки. Редактируемые исходники схем находятся в `docs/diagrams/`.

## Как посмотреть текущий прототип

Откройте `prototype/snapshot/ru/index.html` или `prototype/snapshot/kk/index.html` через локальный HTTP-сервер с корнем `prototype/snapshot/`: страницы используют абсолютные пути `/static/`. Для повторения аудита из корня репозитория выполните `python scripts/audit_snapshot.py`. Инструкцию запуска и тестов самого приложения добавим после появления рабочего кода.

YouTrack пока не создан; подготовленные задачи и критерии готовности есть в документе. После создания проекта добавим сюда ссылку, реальные ID задач — в ветки и PR. Не записываем пароли, ключи и личные данные в Git; конфигурацию новой серверной части оформим отдельными файлами с заглушками.
